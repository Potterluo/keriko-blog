起点是一句不太客气的判断：传统的课程，录播、图文教程、训练营，可能已经不太适合这个时代了。这个判断很空，我想知道具体哪儿不对。聊完之后的结论是：课本身没什么问题，塌的是课程当初成立的那几个假设。假设没了，整套流程就得重画。

后来这场讨论被整理成一份设计稿，重写成这篇文章。中间补了一件事：把图加上。理由在最后一节，这套方案里，图担的是规格的活。

## 0. 材料与口径

原始对话在 [ChatGPT 分享页](https://chatgpt.com/share/6ae40b74-53dc-83ee-85ba-31c8092809c8)。有个坑得先说清楚：那个页面里助手那一侧的消息全部渲染失败，显示成 "Unable to display this message due to an error"，重载也一样，能看到的只有我发出去的六句话。所以正文的框架来自那次会话留下来的整理稿，不是逐字记录；行文、取舍和批评性的段落是我自己的，图是我按这个框架重画的。

那六句话的轨迹是：课程可能不行了 → 能不能设计一套与 AI 共学的模式 → 但别另造工具，寄生在 Codex 上就好 → 但图文教材不能少，防止 Agent 天马行空 → 总结成一份「Agent 时代的课程应该如何设计」→ 全是文字不对，图也得有。

## 1. 塌掉的是假设，不是内容

过去几十年的学习模式很稳定：教材组织知识，教师讲解知识，学生阅读、听课、练习，考试检验。这套流程建立在三个前提上，而这三个前提现在同时不成立了：

| 隐含假设     | 传统课程的应对     | 现在为什么不成立           |
| :----------- | :----------------- | :------------------------- |
| 学习者缺信息 | 系统讲授、线性编排 | 信息不再稀缺，讲全无优势   |
| 瓶颈在解释   | 好老师、好类比     | 解释可按需生成，还能重讲   |
| 练习要人改   | 作业、批改、答疑   | Agent 即时跑改，人成了瓶颈 |

讲得再全，也只是「另一个搜得到的答案」。稀缺的东西换了位置：从获得解释，变成判断答案、提出问题、把事做完。这三件事恰好是传统课程最不训练的部分。它训练的是接受解释，甚至把接受得快当成学得好。

把课做得更好，修不好这个问题。录播换高清、图文换动效、习题换自适应，优化的还是那条正在失效的管道。

![图 1 两种学习系统的形状对比：左侧传统课程是一条单向信息管道，教材与讲授、练习、批改、考试首尾串联，瓶颈落在解释与批改的供给速度上；右侧 Agent-Native 学习系统是一个闭环，知识层给出规范基线，教学层按学习者状态组织过程，学习者层记录能力与错误，四者互相约束而不是单向传递](/img/agent-era-course/fig-01.svg)

## 2. 框架的三层

把上面那三条反过来说，就是框架的三层：

| 层次             | 核心职责                 | 回答的问题 | 主要内容                     |
| :--------------- | :----------------------- | :--------- | :--------------------------- |
| Knowledge 知识层 | 提供经过审核的知识基线   | 学什么     | 教材、定义、公式、图示、代码 |
| Agent 教学层     | 组织并执行教学过程       | 怎么学     | 诊断、规划、讲解、实践、评估 |
| Learner 学习者层 | 记录学习者真正掌握了什么 | 学会了什么 | 能力状态、易错点、实验、复盘 |

关键取舍在这里定了：不开发新的 AI 学习平台，尽量用现成的 Coding Agent。Codex、Claude Code 这类工具已经有文件读写、代码执行、工具调用、任务规划和上下文管理，课程没必要重造一遍基础设施。要建设的是四样东西：结构化教材、可执行的教学工作流、一组职责明确的 Skills、标准化的任务与评估。

同一份教材，针对不同的人应该生成不同的过程。学 Self-Attention：数学强的从 Q/K/V 与矩阵运算进；没数学背景的先讲 Query 找 Key 的直觉再回公式；有工程经验的直接上 PyTorch 和张量维度分析。教材提供稳定基线，Agent 提供灵活教学。这句是整个框架的旋钮。

![图 2 三层架构与六个 Skills：Knowledge 层持教材与评估标准，Agent 只读不写、冲突时举证质疑；Agent 层由 learning-diagnosis、learning-planner、concept-explorer、learning-lab、knowledge-assessment、learning-review 六个 Skill 驱动教学过程；Learner 层的记录写回后决定下一轮从哪里开始](/img/agent-era-course/fig-02.svg)

## 3. 教材：从「文档集合」到「知识资产」

Agent 能动态生成解释，这恰恰是教材不能取消的理由。它会在数学推导、系统架构、算法原理这些地方生成看起来合理、实际不准确的内容，而一个错误的前提会让后面所有内容一起偏。教材因此要担一个角色：规范知识基线（Canonical Knowledge）。教材里每句话不必都是不可质疑的真理，但核心知识必须来源明确、经过审核、版本可追踪。

教材的形态要从「文档」改成「模块」。一个模块大致有这么几件东西，不必全有，但缺哪件要说得清：

| 部件                | 作用                 |
| :------------------ | :------------------- |
| Learning Objectives | 明确这一节要能做什么 |
| Concept             | 核心概念与原理       |
| Visualization       | 图示、流程图、架构图 |
| Mathematics         | 公式与推导           |
| Examples            | 具体例子             |
| Code                | 可运行的实现         |
| Pitfalls            | 常见错误与误区       |
| References          | 参考资料与出处       |
| Assessment          | 学习评估             |

比部件表更重要的是 Curriculum as Code：课程本身像软件项目一样版本管理，每个模块除人类可读的教材外，还有机器可读的描述。

```yaml
id: transformer.self_attention
title: Self-Attention

objectives:
  - 理解 Query / Key / Value 的角色
  - 理解注意力分数与缩放点积
  - 用 PyTorch 独立实现 self-attention

prerequisites:
  - linear_algebra.matrix_multiplication
  - deep_learning.neural_network
  - python.pytorch_basics

materials:
  - concept.md
  - visualization.svg
  - implementation.ipynb

assessment:
  - explain_attention
  - implement_self_attention
  - analyze_tensor_shapes

mastery_criteria:
  - 能解释注意力机制在做什么
  - 能独立实现 self-attention
  - 能说清 Q/K/V 的维度关系
```

这份元数据解决的是 Agent 的一个实际困难：它不必通读整个仓库去猜「这一节到底要教到哪」，直接读到边界、前置和判定标准就行。教材顺带也变成了可以被 review、被 diff、被回滚的东西。

## 4. 约束 Agent：三级知识权限

Agent 的灵活是优势，也是风险。如果允许它任意解释核心知识，不同学习者会拿到互相矛盾的定义。这在教学里不是小事。

所以要把知识分成三级权限：

| 层级                      | 包含什么                   | Agent 的权限               |
| :------------------------ | :------------------------- | :------------------------- |
| L1 · Canonical Knowledge  | 定义、公式、推导、算法原理 | 必须遵循；质疑要举证       |
| L2 · Adaptive Explanation | 分级解释、类比、示例、练习 | 可生成，须与 L1 一致       |
| L3 · Exploration          | 论文、前沿、未共识问题     | 可越界，须标注来源与确信度 |

配套还有一条更实用的要求：Agent 输出时要区分四种东西，教材已确认的、外部资料给出的事实、它自己的推断、尚未验证的观点。四样混在一起说，幻觉就藏在这里。

核心原则是：Agent 可以自由改变教学方式，但不能随意改变知识本身。

![图 3 三级知识权限：L1 规范知识由教材与人工审核持有，Agent 只能遵循或举证质疑；L2 动态解释允许 Agent 在 L1 约束内自由生成；L3 探索区允许它越界，但必须显式标注来源与确信度](/img/agent-era-course/fig-03.svg)

## 5. 流程：EUBVR，命门在 Verify

学习从「先读后练最后考」变成持续循环：Explore → Understand → Build → Verify → Reflect。

- Explore 探索：先用问题建立动机。学 KV Cache 之前先问，为什么长文本推理时速度和显存会变？为什么重复计算历史 Token 的 K/V 是浪费？
- Understand 理解：按教材讲，配图、配公式、按难度给多版解释。但不能一路输出答案，得反问。讲完 Attention 公式，先别给答案，让它解释为什么除以 √d_k。
- Build 动手：这是变化最大的一环，建环境、写代码、跑实验、看结果，Agent 都能带着做。界线要划清楚，帮你搭环境不等于替你学习。
- Verify 验证：整个循环里最关键的一环，下面单独说。
- Reflect 复盘：学会了什么、哪里还模糊、错在哪、下一步学什么，写回学习者层，成为下一轮的起点。

Verify 最容易造假，三种假象最常见：

1. Agent 出题、Agent 判分。流程看着完整，其实是同一个东西给自己盖章，最后告诉学习者「你已经掌握了」。这比没有评估更危险。
2. 代码跑通就算掌握。跑通只证明机器对了，不证明人懂了。
3. 顺畅就算会了。Agent 的流畅会稳定地掩盖理解的真空，越顺手越要警惕。

能用的验证方式反而是很朴素的几件事：不看教材解释核心概念；不依赖 Agent 独立实现关键代码；分析一个没见过的案例；改参数并预测结果；解释代码里每一步为什么这么写；换场景迁移。

这条线站内之前从工程角度写过一次：[VibeCoding 实战：从 AI 实习生到 AI 善后工程师](/posts/003-vibecoding)。放到学习场景里，话可以更硬：凡是能由 Agent 自己判定通过的环节，都不算验证。

![图 4 EUBVR 学习循环：Explore 建立动机、Understand 建立理解、Build 建立经验、Verify 独立验证、Reflect 沉淀并更新学习者状态，然后回到下一轮。Verify 被单独高亮，因为它是唯一能挡住「Agent 替学习者完成学习」的环节；下方三张卡片是它最常见的三种造假方式](/img/agent-era-course/fig-04.svg)

## 6. 评价：从章节导向到能力导向

传统课程以章节为轴：学完第一章进第二章，全部学完，课程结束。这套安排假设所有人起点相同、路径相同，而事实是有人缺线性代数、有人只补 Transformer、有人目标就是推理工程。

所以课程的轴要换，从 Chapter-Oriented 转向 Competency-Oriented。每个模块定义学习目标、前置知识、核心材料、实践任务、评估标准、掌握程度；每个人的路径可以不同，终点标准必须一样。

| 维度     | 章节导向       | 能力导向           |
| :------- | :------------- | :----------------- |
| 组织单位 | 章、节、课时   | 能力模块           |
| 进度依据 | 学完前一章     | 通过评估、补齐前置 |
| 个性化   | 弱，最多快慢班 | 强，路径可重组     |
| 完成标准 | 全部章节结束   | 达到明确的能力标准 |

能力本身分三级，这样「掌握」才不是一句形容词：

| 等级               | 状态 | 典型表现                       |
| :----------------- | :--- | :----------------------------- |
| Level 1 Understand | 理解 | 能解释概念与原理               |
| Level 2 Apply      | 应用 | 能用它解决具体问题             |
| Level 3 Master     | 掌握 | 能独立实现、分析并迁移到新场景 |

配套的观念要改：时间不算标准，能力才算。20 小时入门、40 小时理解与实践、80 小时工程深入，这些只是预估，不能当成「学完」的凭证。

## 7. 落地：一个主 Agent 加一组 Skills

第一版不做多 Agent 系统，一个主 Agent 加一组职责明确的 Skills 就够了。

| Skill                | 职责               |
| :------------------- | :----------------- |
| learning-diagnosis   | 诊断学习者基础     |
| learning-planner     | 制定学习路径       |
| concept-explorer     | 讲解与探索知识     |
| learning-lab         | 创建并执行实践实验 |
| knowledge-assessment | 评估掌握程度       |
| learning-review      | 复盘并更新学习状态 |

边界要清楚：教材负责教什么，Skills 负责如何教，Coding Agent 负责运行，Learner State 负责记录结果。这样一来不必维护独立的 Agent Runtime，也不绑定某一家厂商，Skills 可以一个个加。

落到文件系统，课程就是一个仓库：

```text nocollapse
agent-native-learning/
├── README.md
├── AGENTS.md                      # 教学规则：角色、权限、边界
├── .agents/skills/                # 六个 Skill，各自一个目录
├── knowledge/                     # 教材：按能力模块组织，非章节
│   ├── foundations/
│   ├── machine-learning/
│   ├── deep-learning/
│   ├── transformer/
│   ├── llm/
│   └── llm-engineering/
├── labs/                          # 可运行实验
├── assessments/                   # 任务与评估标准
├── schemas/                       # module / assessment 的 JSON Schema
└── learner/                       # 个人状态：profile / progress / mistakes / journal
```

![图 5 课程仓库的寄生结构：上层是宿主 Coding Agent（Codex、Claude Code 等），提供模型、工具与执行能力；下层是课程仓库，教材、实验、评估与 Skill 都是纯文本资产，可以被不同宿主复用；右侧 learner 目录记录个人状态并回灌给 Agent，决定下一轮从哪里开始](/img/agent-era-course/fig-05.svg)

### MVP：先验证一个闭环

不要一上来就建完整的 ML → DL → LLM 课程。选一个边界清楚、复杂度够的模块，Transformer Self-Attention，目标是让一个没有 Transformer 基础的开发者，在 Agent 辅助下最终能独立理解并实现它。流程是：诊断基础 → 生成路径 → 引导讲解 → 展示原理图与公式 → 建 PyTorch 实验 → 协作实现 → 给不含答案的挑战 → 通过代码、解释与迁移任务评估 → 更新学习状态与错误记录。

第一阶段该验证的是六个问题，跟教材多丰富、Skill 有多少个无关：

1. Agent 能否正确理解教材，而不是「大致读懂」？
2. 能否按基础调整教学，而不是套模板？
3. 能否有效引导实践，而不越位代做？
4. 能否识别学习者真正不懂的地方？
5. 能否区分「Agent 完成了任务」和「学习者掌握了知识」？
6. 能否让学习者在没有 Agent 帮助时独立完成？

这六条过不了，框架就还只是设想。

## 8. 为什么图不能省

对话结尾我补了一句：「全是文字不对吧，也可以嵌入 SVG 这些图形，方便理解。」这句要是被当成排版建议，就亏了。

先说做什么：不同类型的内容交给不同的视觉格式，别为了有图而塞装饰图。

| 格式             | 适合表达               | 特点                     |
| :--------------- | :--------------------- | :----------------------- |
| SVG              | 架构图、原理图、示意图 | 矢量、可缩放、可版本管理 |
| Mermaid          | 流程图、状态机、关系图 | 纯文本维护，Agent 能改   |
| PNG / WebP       | 复杂插图、实验截图     | 表现力强                 |
| GIF / 视频       | 动态过程、算法演示     | 展示时间变化             |
| Jupyter Notebook | 交互实验、数据可视化   | 可运行、可改参数         |
| LaTeX            | 数学公式与推导         | 精确表达                 |

再说为什么必须做。图在这套框架里有三种身份，一种比一种硬：

1. 压缩。结构、层次、时序、因果本质是二维的，文字是一维的流。用一维讲二维，读者得在脑子里拼装，拼装失败就被记成「没讲清楚」。
2. 诊断。图画不出来，说明你不懂那条边。文字可以含糊（「然后系统处理一下」），图不行，你必须决定这条线从谁指向谁。
3. 可执行。节点是模块，边是依赖或数据流，纵向是层次，横向是时序。画准的图能直接落成目录结构、接口签名、测试骨架。

第三种身份是 Agent 时代才有的。以前图只给人看，现在图同时给 Agent 读，它从图里拿到的是结构约束，从文字里拿到的只是描述。全是文字的课程今天亏两次：人读不动，Agent 也用不上。

代价也得认。图画错比写错更顽固，因为它看起来确定，人不太会怀疑一张排版整齐的框线图。所以每张图都该能指回去，这张图对应仓库里哪几个文件、哪几个接口。对不上的图，比没有图更糟。

## 9. 代价，以及它不适合谁

- 对学习者门槛更高。能判断的人越练越强；不能判断的人越用越顺，顺到某天发现自己只是很会和 Agent 聊天。
- 寄生意味着版本脆弱。宿主的指令机制、工具接口一改，课程就得跟着改。这是主动换来的不稳定，好处是不被生态甩下。
- 教材维护成本不降反升。精确、可引用、带判据、对应到行号，比写散文累得多。
- 只适合有「可验证动作」的领域。编程、运维、数据分析、实验科学天然有对错；价值判断和审美很难定判据，硬套会退化成聊天，而聊天不产生能力。
- 最大的风险还是顺畅。所有验证机制存在的意义，就是在「顺手」和「会了」之间插一道检查。没有这道检查的共学，只是把刷题换成了刷对话。

## 10. 结论

Agent 时代的课程不是把课讲给 Agent 听，是把课程改造成 Agent 能读、人能判的知识资产。

拆开是四句：

- 教材不消失，它换岗成规范知识基线，负责让分歧有地方可对，而不是负责把所有答案写全。
- 工具不新建，寄生就好。宿主提供发动机，规则、路径和判据自己写。
